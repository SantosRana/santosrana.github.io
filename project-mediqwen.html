Project 004

MediQwen

Offline, privacy-first multimodal clinical AI assistant combining local Qwen inference, LangGraph state-driven orchestration, medical RAG, and deterministic safety guardrails.

100% Local Inference
FSM Safety Routing
RAG Medical Knowledge

System Architecture

Safety-First Routing

User Input -> Guardrails -> Risk Classifier

Every request passes through deterministic validation and dialogue-state routing before model generation. Emergency signals can override normal conversational and retrieval paths.

Multimodal Processing

Text / Image -> Preprocessing -> Clinical Context

MediQwen supports text and medical-image inputs, allowing visual information to participate in the same controlled clinical reasoning workflow.

Knowledge-Grounded Retrieval

Medical Query -> ChromaDB -> Context

Curated medical knowledge is retrieved locally and passed to generation as supporting context, with retrieval intent separated from general conversation and safety decisions.

Controlled Generation

Context + State -> Qwen -> Safe Response

The local LLM generates responses only after routing, risk classification, retrieval, and safety checks establish the appropriate response path.

Core Design Principle

MediQwen does not rely on the LLM alone to decide whether a request is safe. Deterministic guardrails, risk classification, retrieval controls, and response filtering provide a structured safety layer around local model generation.

Agent Workflow

The LangGraph workflow coordinates guardrails, conversational handling, classification, multimodal processing, retrieval, web fallback when appropriate, safe refusal, and final generation as separate controlled stages.

Safety & Reliability

FSM
State-driven routing separates conversational, clinical, and multimodal workflows
4
Risk levels: emergency, high, medium, and low for controlled escalation
RAG
Curated medical knowledge retrieval with source-aware context handling

Emergency Override

High-risk emergency patterns are handled deterministically before normal retrieval and generation, allowing urgent safety messaging to take priority over ordinary assistant behavior.

Prompt-Injection Protection

Adversarial instructions are intercepted by the guardrail layer rather than being passed directly into the clinical generation pipeline.

Retrieval Validation

Retrieved context, distance scores, and metadata can be inspected before LLM generation, reducing the risk of irrelevant knowledge being used to ground a clinical response.

Technical Stack

Qwen Ollama LangGraph ChromaDB LangChain RAG Python PIL Multimodal AI Safety Guardrails Streamlit Pytest

Key Engineering Focus

The project focuses on privacy-first local inference, deterministic safety controls, modular agent orchestration, retrieval-grounded generation, multimodal processing, and automated pipeline evaluation rather than treating the LLM as an unconstrained chatbot.

Why Local?

Running the clinical assistant locally keeps sensitive user inputs within the local environment and avoids sending clinical conversations to a third-party inference service.

Why MediQwen

In remote, mountainous, low-resource regions, such as rural communities in Nepal and the wider Himalayas, qualified clinicians, diagnostic tools and internet access can all be scarce. MediQwen explores how an assistant running entirely on edge hardware, with no internet dependency, could support off-grid health centers, community health workers and field assistants with evidence-grounded triage, clinical image analysis and medical guidance.

Not just a chatbot

Deterministic state transitions, multimodal reasoning, BGE scope classification, hybrid retrieval and multi-layer guardrails replace a single unconstrained LLM call.

Local-first inference

Core LLM inference runs through Ollama on the local machine. Patient prompts and images are never sent to a cloud LLM API.

Evidence-grounded

Responses are built from retrieved medical context, presented with appropriate clinical uncertainty, to reduce hallucination.

System Architecture

Every request moves through a deterministic seven-stage graph before the model is allowed to generate.

Safety-First Routing

Input→Guardrails→Scope Gate→Risk

Regex guardrails and the dialogue-state FSM run before any LLM call. Unsafe or out-of-scope requests go straight to a safe refusal node, bypassing the model in about 0.01 s.

Multimodal Processing

Text / Image→Normalize→Base64 PNG

Clinical images get adaptive normalization, aspect-ratio resizing and PNG Base64 conversion before reaching the local vision-language model.

Hybrid Retrieval

Query→ChromaDB→Web fallback

BAAI/bge-large-en-v1.5 embeddings, score-thresholded diversity retrieval over a local ChromaDB store, and a whitelisted web fallback that is used only in online mode.

Controlled Generation

Context + Risk→Qwen 3.5→Response

The generator combines the query, any image, retrieved knowledge and the risk assessment. A database miss in offline mode ends in a safe refusal rather than a guess.

Processing pipeline

  1. Dialogue Manager FSM & safety checkActs as traffic controller: casual, medical, nutrition or image request. Prompt injections and malicious inputs are blocked deterministically before any LLM runs.
  2. BGE scope classification & decision gateCosine similarity against prototype intent vectors assigns MEDICAL, NUTRITION, CASUAL or OUT_OF_SCOPE.
  3. Clinical risk assessmentClassifies each message into risk tiers and tracks multi-turn worsening. Emergency cases prepend urgent guidance to the response.
  4. Multimodal processingImage normalization, adaptive resizing, Base64 encoding and vision-language preparation.
  5. Retrieval-augmented generationMedical documents converted to structured Markdown are searched locally first, filtering out low-quality matches.
  6. Intelligent web fallbackIf nothing relevant is found locally and online mode is on, trusted sources (NHS, WHO, Mayo Clinic, Healthline) are scraped, cleaned and cached locally for future requests.
  7. Response generationGrounds the answer in retrieved evidence, states clinical uncertainty and encourages professional care when appropriate.

Safety & Reliability

The LLM is never the only line of defense.

Layer 1: Pre-compiled regex guards

Intercept prompt injections, system-prompt leak attempts, self-harm content and code or programming requests before they reach the model.

Layer 2: Risk classifier

Assigns a medical risk tier and escalates when a user reports that symptoms are worsening across turns.

LOW"What is a rash?"Informational query
MEDIUM"I have a rash"Active self-report
HIGH"My rash is spreading"Worsening modifier
EMERGENCY"Crushing chest pain"Emergency signature

Anaphora override

Ambiguous follow-ups like "How can we treat it?" resolve against the active clinical subject and route as MEDICAL.

Technical intercept

Code or technical requests override any active clinical context to prevent domain misuse.

Offline safe refusal

With no local evidence and no network, the system refuses safely instead of improvising medical advice.

Privacy & Responsible Use

Offline mode

Patient images, prompts and medical information stay on the local machine. Knowledge embeddings and cached web content are stored in local ChromaDB stores.

Online mode

Whitelisted medical web sources may be queried for retrieval fallback, so the retrieval request can leave the device. Use it only when that external access is acceptable.

Disclaimer

MediQwen is for research and educational purposes only. It is not a medical device, does not diagnose disease, and does not replace professional medical advice, diagnosis or emergency care.
